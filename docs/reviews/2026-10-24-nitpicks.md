# Nitpick pass: RomanicaClient (2026-10-24)

> Owner-requested sweep for every small thing, on top of the 2026-10-23/24 reviews in this folder. Nothing here repeats those docs unless it's still live. Checks were scripted greps and live `curl`s run on 2026-10-24. Each item names the file:line or URL that shows it. Only the items marked as checked live were run against production.

## Findings

Reviewed `main` @ 934a3b5ba.
- **Translations are a third done, not "all real translations" as the pass-3 review said.** `versions/latest/.../lang/en_us.json` has 240 keys. de_de, es_es and pt_br have 154 each, so 86 keys (36%) fall back to English. **fr_fr has 3 keys.** Either finish French or drop it from the locale list; a 3-key file makes the language look supported when it isn't. A presence test (every en_us key in every shipped locale) would have caught this.
- `fabric.mod.json` `contact.sources` / `contact.issues` point to `github.com/Imperium-MC/ImperiumClient`, the old org (works by redirect). Mod menus show these links. Change them to `Romanica-MC/RomanicaClient`.
- Seven log lines say "ImperiumMC …" (ImperiumChannels.kt:110, ImperiumIntegration.kt:84, EnforcementService.kt:137, ImperiumOnline.kt:104-126). These are what players paste into support threads. Rename them to "Romanica".
- `settings.gradle:33` sets `rootProject.name = "AxolotlClient-mod"`, `gradle.properties` sets `maven_group=io.github.axolotlclient` and `archives_base_name=ImperiumClient`, but the release assets are named `RomanicaClient-…`. That gap forces the manual rename that caused the beta.24 version mixup. Set `archives_base_name=RomanicaClient`.
- Gate strings use `<br>` as a line break (`imperiumclient.gate.*`, and 41 more in the common lang). That works only because AxolotlClient's tooltip renderer splits on it. Any other screen shows a literal `<br>`. Fine, but document it in the lang file's header.
- The gate copy is close but not identical: "has not enabled auto-fishing" (opt-in) vs "has disabled auto-eating" (opt-out). That's accurate, but players read it as inconsistent. Add a tooltip line saying which features are opt-in.
- 45 hardcoded `0xFF…` ARGB colors in custom code, with no palette object. The carved theme has tokens; use them.
- 44 `!!` in custom code.
- `README.md` is clean (Romanica-first, upstream credited). One nit: "usable anywhere" contradicts the enforcement layer being scoped to romanica.net. Say which features only work there.
- From pass 3/4, still open: beta.24 says it's `0.1.0-alpha.1`, `publishMods` targets upstream's projects, and the title screen throws an exception every frame.

## Cross-repo inconsistencies

- **Two vote-site lists.** The website has 9 sites (`romanica-frontend/src/lib/site.ts:26-34`); the plugin has 8 plus 34 (`vote-sites.yml`), and most of the 34 are placeholders. Keep one list, in the backend or the plugin config, and have the other read it.
- **Game version.** The plugin `api-version` is 26.2, and the pack and plugin config say `26.2`. The launcher and client ship 26.3, and the website FAQ meta says "1.8–26.2". Settle one statement of "server runs X, client Y, joinable from Z" and use it everywhere.
- **Social handles** are `@PlayImperiumMC` / `r/ImperiumMC` on the website (`site.ts:11-17`, `llms.txt:147-149`). This is the owner's call: rename the accounts, or keep them and note it.
- **"ImperiumMC" in player-visible strings:** Discord changelog footers (backend), the pack menu description (pack), mod-menu source/issue links (client), and launcher support links. Each is listed in its repo's doc.
- **Protocol-locked old names that must NOT be renamed one-sided:** Redis keys `ImperiumMC:*`, permission nodes `imperiummc.*`, mod id and channels `imperiumclient:*`, env var `IMPERIUMMC_HMAC_SECRET`. Rename them only in a coordinated change across both sides.

## Pass 2 (agent)

Reviewed `main` @ 7d7ef544b (2026-10-24). Scope: `versions/latest/src/main/kotlin/io/github/axolotlclient/imperium/**`, `modules/legions`, `modules/enchantedmc`, and both `en_us.json` files, plus their call sites. Method: scripted scans (option ids vs lang keys, options never read, doc paths that don't resolve, lang wording lint), then reading each hit. Items fixed by the open PRs #29–#32 (mod-menu links, log lines, jar name, title-screen head, publishMods, release version check, de/es/pt/fr) are not repeated here.

### Bugs (behaviour differs from what the code or docs say)

1. **The module menu draws QoL modules as server-blocked on every multiplayer server.** `ImperiumMenuScreen.kt:431-434` sets `isBlocked = ServerGating.tier(id) == LOCKED`, and `GATE_IDS` (`:1818-1827`) includes `auto_eat`, `auto_tool`, `auto_armor`, `auto_reconnect` and `quick_phrases`. `ServerGating.tier` (`ServerGating.kt:86-96`) returns LOCKED for any id without an explicit allow. But the QoL modules use `enforceQoL` (`ServerGating.kt:147-159`), which only locks them on an explicit deny. The result, on any server without an `allow` (a v1 Romanica server or any other server): the cards render red and refuse clicks while the module itself still runs. `docs/server-gated-features.md:59` says QoL modules "ship **enabled**". Fix: map the QoL ids to `session.isDenied(id)`.
2. **The enforcement allowlist was never migrated off `imperiummc.net`.** `EnforcementConfig.kt:45-48` stores the allowlist as a saved `StringOption`, and #21 (`1b185fa2e`) changed only the *default*. Any player whose config was written before #21 still has `imperiummc.net,play.imperiummc.net` saved. For them `isAddressAllowed` (`EnforcementService.kt:186-189`) never matches `play.romanica.net`, so the layer is silently inert. Fix: on load, rewrite an exact old default to the new one, and test that with a pre-#21 config fixture.
3. **The allowlist is a player switch, which breaks the class's own rule.** `EnforcementConfig.kt:33` says "Enforcement is server policy, never a player switch (review #15)", but `server_allowlist` is a plain editable option: clearing it turns enforcement off. Either hide and pin it, or reword the KDoc. The same KDoc is also corrupted: `:30-31` says "two options" when there is one, and `:33-34` breaks off mid-sentence ("there is no enabled / completely inert").
4. **Breadcrumbs are keyed by dimension, not server.** `Breadcrumb.kt:36` and `BreadcrumbManager.kt:48,81` persist one global list in the config, keyed only by `dimension`. A trail dropped in Romanica's overworld is drawn in every other server's and every singleplayer world's overworld. Nothing clears it on disconnect; the only `clearAll()` calls are the HUD's buttons, `BreadcrumbsHud.kt:88,217`. Key it by server address or world id.
5. **`EmoteDispatch.reset()` has no caller.** `EmoteDispatch.kt:46-49` documents it as "what disconnect / channel loss should do", but no DISCONNECT handler calls it (`grep -rn "EmoteDispatch.reset" versions/` is empty). It's latent today, since nothing calls `set()` outside tests, but the first cosmetics-channel dispatcher will leak across servers. Wire it into the `ImperiumChannels.kt:104-108` DISCONNECT block now.
6. **The legion API fallback writes the registry from an HTTP thread.** `ImperiumOnline.kt:163-166` runs `applyIfVacant` in `thenAccept`, off the client thread. Its check-then-set (`get() != null` then set, `:212-214`) can interleave with a channel push applied on the client thread (`ImperiumChannels.kt:93-101` uses `ctx.client().execute`). Hop to `Minecraft.getInstance().execute` before applying.
7. **The CI gametest never gets a window. It isn't just slow.** Run 40068414731 (this pass, `fix/branding-metadata`), `gametest-run/logs/latest.log` shows `Failed to create backend OpenGL … Couldn't find matching GLX visual`, then `Failed to create backend Vulkan … VK_KHR_surface`. The job then sits until its 90-minute timeout. The comment in `.github/workflows/ci.yml:41-58` blames llvmpipe speed ("boot, not the tests, is the wall"), but the real blocker is the xvfb/GLX setup (for example `-screen 0 1280x1024x24 +extension GLX`, or a GLX visual SDL3 accepts). Until this is fixed, no PR can get in-game evidence from CI.

### Settings with no lang key (render as the raw id)

8. `Hitboxes.kt:61` declares `BooleanOption("show_eye_line")`, but the lang key is `hitboxes.show_eye_line` (`en_us.json:84`). The option shows the literal `show_eye_line`, and the lang entry is never used. Rename the option id; that resets this one saved value.
9. `CooldownsHud.kt:57,60,63,67`: `showitemname`, `showseconds`, `barcolor` and `barthickness` have no key in either `en_us.json`.
10. `EntityCountHud.kt:45`: `display_total_count` has no key.
11. Not a bug, noted so the next pass doesn't re-report it: `EmoteWheelConfig.kt:57` builds `"emote." + n` and `QuickPhrases.kt:65` builds `"quick_phrase_" + n`. The scanner flags both, but the keys exist.

### HUD defaults that overlap

12. All eight Romanica-added HUDs keep `HudEntry`'s default position of (0.0, 0.0) (`common/.../HudEntry.kt:66-68`): none of `LegionHud`, `BoostsHud`, `CooldownsHud`, `EntityCountHud`, `BlockCoordinatesHud`, `BreadcrumbsHud`, `WaypointsHud` (`versions/latest/.../hud/simple/*.kt`) or `NowPlayingHud` overrides `getDefaultX/Y`. `NowPlayingHud` only sets its anchor to BOTTOM_LEFT (`NowPlayingHud.kt:178`), which changes the growth direction, not the position. Turning on the three Romanica HUDs a player is told to use (legion, boosts, cooldowns) stacks them on the same pixel. Give each a default slot, for example a left column at y = 0.30 / 0.36 / 0.42.
